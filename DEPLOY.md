# Как залить проект на GitHub и развернуть на VPS

Гайд рассчитан на то, что вы делаете это впервые. Команды, которые нужно ввести, выделены отдельными блоками. Вместо `ВАШ_ЛОГИН`, `IP_СЕРВЕРА` и других слов КАПСОМ подставляйте свои значения.

---

## Часть 1. Заливаем проект на GitHub

### Шаг 1. Установите Git

- **Windows:** скачайте установщик с https://git-scm.com/download/win и при установке везде жмите «Next».
- **macOS:** выполните в терминале `xcode-select --install`.
- **Linux:** `sudo apt install git`.

Проверьте установку:
```bash
git --version
```

Один раз представьтесь Git (эти имя и email будут видны в истории коммитов):
```bash
git config --global user.name "Иван Иванов"
git config --global user.email "ваш@email.ru"
```

### Шаг 2. Создайте репозиторий на GitHub

1. Зайдите на https://github.com и войдите в аккаунт (или зарегистрируйтесь).
2. Справа вверху нажмите **+** → **New repository**.
3. В поле **Repository name** напишите `videohosting`.
4. Выберите **Public** (видно всем, удобно показать преподавателю) или **Private**.
5. Галочки «Add a README», «.gitignore» и «license» **не ставьте**: эти файлы уже есть в проекте.
6. Нажмите **Create repository**.

### Шаг 3. Создайте токен для входа

GitHub не принимает обычный пароль при `git push`, вместо него нужен токен.

1. Откройте https://github.com/settings/tokens → **Generate new token** → **Generate new token (classic)**.
2. В поле **Note** напишите `videohosting`, в **Expiration** выберите 90 дней.
3. Отметьте галочку **repo**.
4. Нажмите **Generate token** и **сразу скопируйте токен** (начинается с `ghp_`). Второй раз GitHub его не покажет.

### Шаг 4. Отправьте код

Распакуйте архив, откройте терминал в папке `videohosting` (на Windows: правый клик по папке → «Open Git Bash here») и выполните:

```bash
git init
git add .
git commit -m "Курсовая: бэкенд видеохостинга на Go + фронтенд"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/videohosting.git
git push -u origin main
```

Когда Git спросит логин и пароль: логин — ваш логин GitHub, вместо пароля вставьте **токен** из шага 3. Символы при вставке не отображаются, это нормально.

Обновите страницу репозитория на GitHub: файлы должны появиться.

> **Важно:** файл `.env` с паролями в репозиторий не попадёт, он добавлен в `.gitignore`. Так и должно быть: секреты на GitHub не выкладывают.

### Как отправлять изменения потом

```bash
git add .
git commit -m "что поменяли"
git push
```

## Часть 2. Разворачиваем на VPS

### Шаг 1. Арендуйте сервер

Подойдёт любой VPS-хостинг (Timeweb Cloud, Selectel, REG.RU, Beget, Aeza и т. п.). Параметры:

| Параметр | Минимум |
|---|---|
| ОС | **Ubuntu 24.04** (или 22.04) |
| CPU | 1–2 ядра |
| RAM | **2 ГБ** (с 1 ГБ тоже заработает, но обязательно сделайте шаг 3 про swap) |
| Диск | 20 ГБ и больше, в зависимости от того, сколько видео будет |

После оплаты хостинг пришлёт **IP-адрес** и **пароль root**.

### Шаг 2. Подключитесь к серверу

В терминале (на Windows подойдёт PowerShell или Git Bash) выполните:
```bash
ssh root@IP_СЕРВЕРА
```
На вопрос `Are you sure you want to continue connecting` ответьте `yes`, затем введите пароль (символы не отображаются).

Все дальнейшие команды выполняются **на сервере**.

Обновите систему:
```bash
apt update && apt upgrade -y
```

### Шаг 3. Добавьте swap (если RAM 2 ГБ или меньше)

Сборка Go-сервисов в Docker требует памяти. Без swap на маленьком сервере сборка может упасть с ошибкой `killed`.
```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h
```
В строке `Swap` должно появиться `2.0Gi`.

### Шаг 4. Установите Docker

```bash
curl -fsSL https://get.docker.com | sh
docker --version
docker compose version
```
Обе команды должны вывести версии.

### Шаг 5. Настройте файрвол

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw --force enable
ufw status
```

> Postgres (5432) и Redis (6379) в `docker-compose.yml` привязаны к `127.0.0.1`, поэтому из интернета они недоступны. Это важно: Docker умеет открывать порты в обход ufw.

### Шаг 6. Скачайте проект

```bash
apt install -y git
cd /opt
git clone https://github.com/ВАШ_ЛОГИН/videohosting.git
cd videohosting
```
Если репозиторий приватный, Git спросит логин и токен, как в части 1.

### Шаг 7. Настройте секреты

```bash
cp .env.example .env
openssl rand -hex 32   # скопируйте результат, это будет JWT_SECRET
openssl rand -hex 16   # скопируйте результат, это будет пароль базы
nano .env
```

Приведите файл к такому виду, подставив свои значения:
```
JWT_SECRET=длинная_строка_из_первой_команды
POSTGRES_PASSWORD=строка_из_второй_команды
APP_PORT=80
```
Сохраните файл: `Ctrl+O`, `Enter`, затем выйдите: `Ctrl+X`.

> Пароль базы задаётся **до первого запуска**. Если поменять его позже, Postgres его не подхватит, потому что база уже создана со старым паролем. Как это исправить, см. в разделе «Если что-то пошло не так».

### Шаг 8. Запустите

```bash
docker compose up -d --build
```
Первая сборка займёт 3–10 минут. Затем проверьте статус:
```bash
docker compose ps
```
Сервисы `api-gateway`, `auth-service`, `video-service`, `interaction-service`, `postgres` и `redis` должны быть в статусе `running`. Контейнеры `migrate-*` должны завершиться с `exited (0)`: они применяют миграции и выключаются, так и задумано.

Проверьте, что все сервисы живы:
```bash
curl http://localhost/health
```
Ответ должен быть таким: `{"services":{...все "ok"...},"status":"ok"}`.

### Шаг 9. Откройте сайт

В браузере перейдите на `http://IP_СЕРВЕРА`. Зарегистрируйтесь, загрузите видео, оставьте комментарий.

Можно прогнать автотест API, например с сервера:
```bash
API=http://localhost ./scripts/smoke_test.sh
```
Учтите, что тест создаёт тестовых пользователей (`alice…`, `bob…`) в вашей базе.

## Часть 3. Как выкатить обновление (новый архив от Claude)

Данные (пользователи, видео, комментарии) при обновлении **сохраняются**: они лежат в Docker-томах, а новые таблицы и колонки добавят миграции.

### Шаг 1. Замените файлы в своей папке проекта (на ПК)

1. Распакуйте новый архив во **временную** папку.
2. Откройте свою папку проекта, ту, в которой лежит скрытая папка `.git`, и удалите в ней всё, **кроме `.git`**. Так из проекта уйдут файлы, которых больше нет в новой версии (например, старый `frontend/app.js`).
3. Скопируйте содержимое папки `videohosting` из временной папки в папку проекта.

Проверьте, что Git видит изменения:
```bash
git status
```
Новые файлы будут помечены зелёным или как `untracked`, изменённые — `modified`, удалённые — `deleted`.

### Шаг 2. Отправьте изменения на GitHub

```bash
git add -A
git commit -m "Превью, аватарки, плеер, рекомендации, ответы, админ-панель"
git push
```
`-A` нужен, чтобы в коммит попали и удалённые файлы.

### Шаг 3. Обновите сервер

Подключитесь к серверу (`ssh root@IP_СЕРВЕРА`) и выполните:
```bash
cd /opt/videohosting
git pull
docker compose up -d --build
```
Docker пересоберёт изменённые сервисы. Контейнеры `migrate-*` автоматически применят новые миграции `000002_*`.

Проверьте, что всё поднялось:
```bash
docker compose ps -a
curl http://localhost/health
```
- Контейнеры `migrate-*` должны быть в статусе `exited (0)`, остальные — `running`.
- `curl` должен вернуть `"status":"ok"`.

### Шаг 4. Получите права администратора

- **Если пользователя `apr1l` ещё нет**, зарегистрируйте его на сайте **сразу после обновления**: права получает тот, кто первым займёт этот логин.
- **Если `apr1l` уже есть**, выйдите из аккаунта и войдите снова: права записываются в токен при входе.

После входа в шапке появится ссылка «Админка».

Админов можно задать и другим списком: допишите в `.env` строку `ADMIN_USERNAMES=apr1l,другой_логин` и выполните `docker compose up -d`. Кроме того, админ может выдавать права прямо в админ-панели.

### Шаг 5. Обновите страницу в браузере

Нажмите `Ctrl+F5` (на Mac: `Cmd+Shift+R`).

У видео, загруженных до обновления, превью нет: они показываются цветным «кадром плёнки». Чтобы добавить превью, откройте видео, нажмите **«Изменить»**, поставьте плеер на нужный момент и нажмите **«Взять текущий кадр»**. Это может сделать автор или админ.

### Если миграция не прошла

Посмотрите лог:
```bash
docker compose logs migrate-auth migrate-video migrate-interaction
```
Если там `Dirty database version 2`, миграция прервалась на середине. Скопируйте лог мне, я подскажу, как починить, не теряя данных.

## Повседневные команды (выполняются в `/opt/videohosting`)

| Что сделать | Команда |
|---|---|
| Обновить после `git push` | `git pull && docker compose up -d --build` |
| Логи всех сервисов | `docker compose logs -f --tail=100` |
| Логи одного сервиса | `docker compose logs -f video-service` |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose down` |
| Бэкап базы | `docker compose exec -T postgres pg_dumpall -U postgres > backup.sql` |
| Зайти в базу | `docker compose exec postgres psql -U postgres -d video_db` |
| Сколько места заняли видео | `docker system df -v \| grep videos` |

Если поменяли только файлы фронтенда (`frontend/`), пересобирать ничего не нужно: достаточно `git pull` и обновить страницу в браузере.

## Если что-то пошло не так

**Сборка падает с `killed` или `signal: killed`.** Не хватает памяти, сделайте шаг 3 (swap).

**`Bind for 0.0.0.0:80 failed: port is already allocated`.** Порт 80 занят, часто хостинг предустанавливает nginx или apache. Остановите их:
```bash
systemctl stop nginx apache2 2>/dev/null; systemctl disable nginx apache2 2>/dev/null
docker compose up -d
```

**Сайт не открывается по IP.** Проверьте по порядку:
1. `docker compose ps`: работает ли `api-gateway`.
2. `ufw status`: открыт ли порт 80.
3. Панель хостинга: у некоторых провайдеров есть отдельный внешний файрвол, где тоже нужно разрешить порт 80.

**Сервис постоянно перезапускается (`restarting`).** Посмотрите причину в логах: `docker compose logs auth-service`. Чаще всего это `password authentication failed`: пароль в `.env` поменяли после первого запуска. Если данные не жалко, пересоздайте базу:
```bash
docker compose down -v      # ВНИМАНИЕ: удаляет базу и все видео
docker compose up -d --build
```

**`permission denied: ./scripts/smoke_test.sh`.** Выполните `chmod +x scripts/smoke_test.sh`.

**Видео больше 500 МБ не загружается.** Это ограничение из `docker-compose.yml` (`MAX_UPLOAD_MB`). Его можно увеличить и выполнить `docker compose up -d`.

## Домен и HTTPS (по желанию)

Для курсовой достаточно доступа по `http://IP`. Если захотите красивый адрес вида `https://kadr.ru`:
1. купите домен у регистратора;
2. в DNS добавьте A-запись, указывающую на IP сервера;
3. поставьте перед gateway обратный прокси с автоматическим сертификатом Let's Encrypt (проще всего Caddy, это ещё один контейнер в `docker-compose.yml`).

Caddy — новый компонент стека, поэтому сначала согласуйте его, а я потом добавлю конфиг.
