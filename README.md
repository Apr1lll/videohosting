# Videohosting — бэкенд видеохостинга на Go (микросервисы)

Курсовая работа: видеохостинг «Кадр». Пользователи регистрируются, загружают и смотрят видео (с перемоткой), оставляют комментарии, ставят лайки и подписываются на каналы.

Проект состоит из бэкенда (4 микросервиса на Go) и фронтенда (одностраничное приложение на чистом HTML/CSS/JS, без сборки и фреймворков).

Как залить на GitHub и развернуть на VPS — пошагово в [DEPLOY.md](DEPLOY.md).

## Архитектура

```
                    ┌──────────────────────┐
  браузер ──HTTP─▶  │  api-gateway :8080   │  JWT, маршрутизация, rate limit, раздача фронтенда
                    └───┬────────┬────────┬┘
                        │        │        │
              ┌─────────▼──┐ ┌───▼──────────┐ ┌▼────────────────────┐
              │auth-service│ │video-service │ │interaction-service  │
              │   :8081    │ │    :8082     │◀┼▶      :8083         │
              └─────┬──────┘ └──┬───────┬───┘ └──┬──────────┬───────┘
                    │           │       │        │          │
               auth_db     video_db   Redis   interaction_db  Redis
                         + volume с файлами
```

| Сервис | Ответственность | Хранилище |
|---|---|---|
| **api-gateway** | Единая точка входа. Отдаёт фронтенд (всё, что не API, — файлы из `frontend/`). Проверяет JWT и передаёт `X-User-ID` / `X-Username` в сервисы. Закрывает `/internal/*`. Rate limit (300 запросов/мин с IP), CORS, `X-Request-ID`, сводный `/health` | — |
| **auth-service** | Регистрация, вход (bcrypt + JWT HS256), профиль | `auth_db.users` |
| **video-service** | Загрузка (mp4/webm/mov/mkv, до 500 МБ), поиск, карточка, стриминг с `Range`, удаление, топ популярных | `video_db.videos`, файлы в volume, Redis |
| **interaction-service** | Комментарии, лайки/дизлайки, подписки | `interaction_db.*`, Redis |

**Принципы:**
- **Database per service**: у каждого сервиса своя БД, чужие таблицы он не читает.
- **Межсервисное общение по REST:**
  - interaction → video: проверка, что видео существует;
  - interaction → auth: проверка, что канал существует;
  - video → interaction: удаление комментариев и лайков удалённого видео.
- **Слоистая структура** внутри сервиса: `handler` (HTTP) → `service` (бизнес-логика) → `repository` (SQL). Сервис зависит от интерфейсов, а не от конкретных реализаций.

**Как используется Redis:**
- карточки видео кешируются на 5 минут;
- топ популярных кешируется на 1 минуту;
- просмотры копятся в Redis (`INCR`) и раз в 30 секунд пачкой записываются в Postgres, чтобы не делать `UPDATE` на каждый просмотр;
- счётчики лайков и дизлайков кешируются и сбрасываются при каждом изменении.

## Стек
Go 1.23+, PostgreSQL 16, Redis 7, Docker Compose, golang-migrate.

Библиотеки: `jackc/pgx/v5`, `redis/go-redis/v9`, `golang.org/x/crypto/bcrypt`, `golang-jwt/jwt/v5`. Роутинг сделан на стандартном `net/http` (шаблоны вида `GET /videos/{id}` из Go 1.22).

## Запуск

```bash
docker compose up --build
```

Postgres создаёт три базы (`postgres/init.sql`), затем контейнеры `migrate-*` применяют миграции, и только после этого стартуют сервисы. Сайт и API доступны на `http://localhost:8080`.

Пароли и порт задаются в `.env` (образец — `.env.example`).

Сквозной тест (47 проверок через curl; админские запускаются, если передать `ADMIN_EMAIL` и `ADMIN_PASSWORD`):
```bash
./scripts/smoke_test.sh
```

Остановить: `docker compose down`. Остановить и удалить данные: `docker compose down -v`.

## API

Запросы, отмеченные 🔒, требуют заголовок `Authorization: Bearer <token>`. Запросы с 👑 доступны только администратору.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/auth/register` | `{username, email, password}` |
| POST | `/auth/login` | `{email, password}` → `{token, expires_at, user}` |
| GET 🔒 | `/users/me` | свой профиль |
| PATCH 🔒 | `/users/me` | `{bio}` |
| PUT 🔒 | `/users/me/avatar` | multipart: `avatar` (JPEG/PNG/WebP до 2 МБ) |
| DELETE 🔒 | `/users/me/avatar` | удалить аватарку |
| GET | `/users/{id}` | публичный профиль |
| GET | `/users/{id}/avatar` | картинка аватарки; если её нет — SVG с первой буквой имени |
| POST 🔒 | `/videos` | multipart: `title`, `description`, `duration`, `thumbnail`, `file` |
| GET | `/videos?search=&author_id=&page=&limit=` | список и поиск |
| GET | `/videos/popular` | топ-10 по просмотрам |
| GET | `/videos/{id}` | карточка видео |
| PATCH 🔒 | `/videos/{id}` | `{title, description}` — автор или админ |
| DELETE 🔒 | `/videos/{id}` | автор или админ |
| GET | `/videos/{id}/stream` | видеофайл (поддерживает `Range`) |
| GET / PUT 🔒 | `/videos/{id}/thumbnail` | превью / заменить превью |
| GET | `/videos/{id}/recommendations` | рекомендации: автор → похожие → остальные |
| POST 🔒 | `/videos/{id}/comments` | `{text, parent_id?}` — комментарий или ответ |
| GET | `/videos/{id}/comments?page=&limit=` | комментарии верхнего уровня с `reply_count` |
| GET | `/comments/{id}/replies` | ответы на комментарий |
| PATCH / DELETE 🔒 | `/comments/{id}` | изменить / удалить: автор или админ |
| POST 🔒 | `/videos/{id}/like`, `/dislike` | повторное нажатие снимает реакцию |
| GET | `/videos/{id}/reactions` | лайки, дизлайки и своя реакция |
| POST / DELETE 🔒 | `/channels/{id}/subscribe` | подписаться / отписаться (видео на канале не обязательны) |
| GET | `/channels/{id}/subscribers` | число подписчиков |
| GET 🔒 | `/users/me/subscriptions` | на кого я подписан |
| GET 🔒 | `/users/me/subscribers` | кто подписан на меня |
| GET 👑 | `/admin/users?search=&page=` | все пользователи с email и ролью |
| PATCH 👑 | `/admin/users/{id}` | `{role?, bio?, password?}` |
| DELETE 👑 | `/admin/users/{id}` | удалить пользователя со всеми его данными во всех сервисах |
| DELETE 👑 | `/admin/users/{id}/avatar` | убрать аватарку |
| GET 👑 | `/admin/videos/stats` | число видео, просмотров, объём на диске |
| GET 👑 | `/admin/comments?search=&page=` | все комментарии сайта |
| GET 👑 | `/admin/interactions/stats` | комментарии, лайки, подписки |
| GET | `/health` | состояние всех сервисов |

### Роли и админ-панель

У пользователя есть роль `user` или `admin`. Пользователи из переменной `ADMIN_USERNAMES` (по умолчанию `apr1l`) получают роль `admin` при регистрации и при каждом входе. Администратор может выдавать и снимать права у других прямо в админ-панели.

Как проверяется роль:
1. Роль записывается в JWT.
2. Gateway кладёт её в заголовок `X-User-Role`, а такой же заголовок от клиента выбрасывает.
3. Пути `/admin/*` gateway пропускает только администраторам.
4. Каждый сервис проверяет роль ещё раз (защита в глубину).

### Рекомендации

`GET /videos/{id}/recommendations` сортирует видео одним SQL-запросом в три яруса:
1. **Другие видео этого автора.**
2. **Похожие по теме.** Из названия и описания текущего видео собирается запрос `слово1 | слово2 | …`, и выбираются ролики, где совпадает хотя бы одно слово. Используется полнотекстовый поиск PostgreSQL со словарём `russian`, поэтому «котики» и «котиков» считаются одним словом. Внутри яруса ролики сортируются по релевантности `ts_rank`; для скорости есть GIN-индекс.
3. **Все остальные** — по популярности.

### Превью без ffmpeg

Кадры для превью и длительность видео достаёт **браузер** при загрузке файла (`<video>` + `<canvas>`). На сервер уходит готовый JPEG, поэтому серверу не нужен ffmpeg. Если браузер не умеет показывать формат (бывает с mkv/mov), можно загрузить свою картинку. Автор или админ может сменить превью позже, в том числе взять текущий кадр прямо из плеера.

### Скорость загрузки

Видео принимается потоково (`MultipartReader`) и пишется сразу в хранилище. Раньше `ParseMultipartForm` сначала сохранял файл во временную папку, и он копировался второй раз. Видео, превью и аватарки отдаются с заголовками кеширования, поэтому повторный просмотр не скачивает файл заново.

### Примеры

```bash
curl -X POST localhost:8080/auth/register -H 'Content-Type: application/json' \
  -d '{"username":"alice","email":"alice@mail.ru","password":"secret123"}'

TOKEN=$(curl -s -X POST localhost:8080/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"alice@mail.ru","password":"secret123"}' | sed 's/.*"token":"\([^"]*\)".*/\1/')

curl -X POST localhost:8080/videos -H "Authorization: Bearer $TOKEN" \
  -F "title=Котики" -F "description=смешные" -F "file=@cats.mp4"

curl localhost:8080/videos?search=кот
```

Видео можно открыть прямо в браузере: `http://localhost:8080/videos/1/stream`. Перемотка работает.

Ошибки всегда возвращаются в формате `{"error": "описание"}` с соответствующим HTTP-кодом: 400, 401, 403, 404, 409, 413, 429, 502.

## Фронтенд

Папка `frontend/`: `index.html`, `styles.css`, `app.js`. Hash-роутинг (`#/video/5`, `#/channel/2`), поэтому адреса страниц не пересекаются с адресами API.

Код разбит на ES-модули в `frontend/js/`:
- `core.js` — сессия, API, форматирование, работа с картинками;
- `player.js` — плеер;
- `watch.js` — страница видео;
- `channel.js` — канал;
- `upload.js` — загрузка;
- `admin.js` — админ-панель;
- `main.js` — роутер и остальные страницы.

| Страница | Что умеет |
|---|---|
| Главная | новые видео с превью, длительностью и аватарками авторов; вкладка «Популярное» |
| Поиск | по названию, описанию и автору |
| Видео | собственный плеер, лайки, подписка, рекомендации справа, комментарии с ответами, редактирование |
| Канал | аватарка (смена и удаление), описание, подписка (даже если видео ещё нет), вкладка «Подписчики» для владельца |
| Подписки | каналы и лента их свежих видео |
| Загрузка | три кадра на выбор для превью или своя картинка; прогресс со скоростью и оставшимся временем |
| Админ-панель | сводка; пользователи (роль, пароль, описание, аватарка, удаление); видео; комментарии |

**Плеер:**
- перемотка перетаскиванием с подсказкой времени, полоса буферизации;
- громкость и скорость (запоминаются), полный экран, «картинка в картинке»;
- горячие клавиши как на YouTube: `Пробел`/`K` — пауза, `J`/`L` — ∓10 с, `←`/`→` — ∓5 с, `↑`/`↓` — громкость, `M` — звук, `F` — полный экран, `0–9` — переход к 0–90 %.

Видео без превью (загруженные до обновления) показываются как кадр плёнки с названием.

## Безопасность
- Пароли хранятся как bcrypt-хеш. При входе с несуществующим email тоже выполняется сравнение хеша, чтобы по времени ответа нельзя было определить, зарегистрирован ли email.
- Gateway удаляет присланные клиентом заголовки `X-User-ID` и `X-Username`, поэтому подделать пользователя нельзя.
- Пути `/internal/*` закрыты снаружи.
- Видеофайлы сохраняются под случайными именами; путь к файлу от клиента не зависит.
- Размер загрузки ограничен, на запросы действует rate limit.
